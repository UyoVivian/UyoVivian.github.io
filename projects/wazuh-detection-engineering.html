CASE STUDY

Turning security telemetry into actionable detections

This project focused on creating custom Wazuh detection logic for security activity that analysts need to identify quickly and consistently. Rather than relying only on default rules, I worked through the detection lifecycle: identifying the behavior, building the rule logic, assigning appropriate severity, mapping the activity to MITRE ATT&CK, and validating that the detection fired as intended.

Detection use cases

The custom rules covered SQL injection activity, cron-based persistence on Linux, and sudo-related privilege escalation. Together, these scenarios demonstrate detection across web application attacks and host-based activity.

Validation approach

I used controlled log testing to confirm that each rule matched the intended activity and produced the expected alert. This validation step was important because a detection is only useful when analysts can trust that the logic works and the resulting alert contains enough context to support investigation.

Security value

The project demonstrates how detection engineering strengthens SOC visibility by translating attacker behaviors into repeatable monitoring logic. MITRE ATT&CK mapping also helps connect individual alerts to recognizable adversary techniques and supports more structured investigation and reporting.
