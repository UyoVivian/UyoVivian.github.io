CASE STUDY

Protecting the infrastructure behind FinTrust

My responsibility on the FinTrust project was to help establish, secure, and maintain the cloud-hosted environment supporting the application. The work focused on reducing unnecessary exposure, strengthening administrative access, improving visibility, and making sure the security controls could be validated.

What I implemented

I hardened SSH access, established role-based access for team functions, applied least-privilege principles, supported secure team connectivity with Tailscale, and integrated the host with Wazuh for centralized monitoring. File Integrity Monitoring and Security Configuration Assessment helped provide visibility into configuration and system changes.

How I validated security

Security validation included reviewing exposed services and listening ports, checking effective SSH configuration, using Lynis to establish a hardening baseline, and providing verification steps so SOC and GRC team members could confirm controls without receiving unnecessary privileges.

Business perspective

The project reinforced an important lesson: protecting infrastructure alone is not enough when the application itself still contains critical weaknesses. For a financial application, application-level exploitation could lead to unauthorized transactions, sensitive data exposure, financial loss, and damage to customer trust. The remediation roadmap therefore prioritized critical application weaknesses while continuing to strengthen monitoring and defensive controls.
